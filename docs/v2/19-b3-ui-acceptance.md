# B3.5 迁移前 UI 验收报告

## 1. 目标与边界

在“已迁移的真实数据副本”上，用真实前端和 WebView2 窗口执行完整操作，确认迁移后的数据不仅能通过 SQL 校验，也能被用户实际创建、编辑、收藏、分类、回收、恢复和删除。

- 输入：`data/b3-drill/drill.db`（由真实库备份迁移得到，7 条笔记、4 个标签）
- 隔离方式：复制到临时目录后启动独立 uvicorn；真实库和演练库都只读
- 窗口：pywebview + 本机 WebView2 Runtime 152.0.4191.66，隐藏窗口
- 数据：仅临时副本；不写真实库，不改演练库

## 2. 执行方式

新增 `tests/frontend/b3_ui_verify.py`，分两个进程执行：

```powershell
.venv\Scripts\python.exe tests/frontend/b3_ui_verify.py --db data/b3-drill/drill.db --root <临时目录>
.venv\Scripts\python.exe tests/frontend/b3_ui_verify.py --db data/b3-drill/drill.db --root <临时目录> --phase reopen
```

第一阶段完成后关闭窗口并停止服务；第二阶段重新启动服务和新窗口，验证“关闭后重新打开”。

## 3. 操作与结果

第一阶段的 32 项检查全部通过：

| 操作 | 观察 |
|---|---|
| 初始加载 | `v2_ready`，6 条活动笔记、1 条回收站、4 个标签、状态“已保存” |
| 编辑真实笔记副本 | 标题修改后服务器保存，界面“已保存” |
| 收藏 | 收藏状态写入服务器，界面“已保存” |
| 标签 | 新建“B3验收标签”并关联到笔记，标签数 4→5 |
| 新建笔记 | 活动笔记 6→7，服务器计数一致 |
| 移到回收站 | 活动 6、回收站 2，服务器 `is_trashed=true` |
| 恢复 | 活动 7、回收站 1，服务器 `is_trashed=false` |
| 永久删除 | 回收站中点击“永久删除”并确认；服务器 `GET /api/v2/notes/{id}` 返回 404 |
| 刷新 | 刷新后仍为 7 条活动、1 条回收站，修改和新笔记仍在 |
| 关闭再打开 | 第二个进程新窗口仍为 7 条活动、1 条回收站、5 个标签 |

第二阶段 15 项检查全部通过，包括：

- 编辑后的笔记仍在
- 新建后恢复的笔记仍在
- 永久删除的笔记不在
- 新标签仍在且仍关联
- 收藏状态仍在
- 活动/回收站/标签计数与第一阶段结束状态一致

## 5. 已知限制

- 本验收使用隐藏窗口和脚本点击，不是人工鼠标操作；但它驱动的是真实前端 DOM、真实 WebView2 和真实 HTTP/DataPort，不是 mock。
- 验收在真实数据的临时副本上执行，真实库仍未迁移。
- 测试标题是验收标记；报告不输出用户原笔记标题或正文。
- 没有验证多窗口并发、断电和磁盘写满；这些仍属于迁移窗口的风险控制项。

结论：迁移后的数据副本通过真实 UI 的完整增删改查、收藏、标签、回收站、恢复、永久删除、刷新和关闭重开验收。
